# Unit 02: LanguageContext (EN/FR)

## Goal

Add a working LanguageContext with EN/FR dictionaries and a toggle, proven on a
single test string on the scaffold page. No visual design beyond the toggle control.

## Design

Toggle can be a simple shadcn `Button` or `Switch` for now; final placement in the
navbar comes in Unit 03.

## Implementation

### Dictionaries
Create `src/data/en.ts` and `src/data/fr.ts` with a typed shape (e.g. a shared
`Translations` interface) and one test key.

### Context
Create `src/context/LanguageContext.tsx` exposing current language, a `setLanguage`
function, and a `t()` accessor. Detect browser language on first load, then persist
the choice in `localStorage`.

### Wiring
Wrap the app in the provider. Replace the scaffold's test string with `t('hero.test')`
or similar, and add a toggle control that switches language live.

### Document metadata
Add a `meta.title` key to both dictionaries. On load and on every language change,
set `document.title` from it and `document.documentElement.lang` to the current
language. Leave the static `<title>` in `index.html` as the fallback: it is the
only allowed hardcoded user-facing string (see `architecture.md`, invariant 1).

## Dependencies

- None beyond what Unit 01 installed

## Verify when done

- [ ] Clicking the toggle switches the test string between EN and FR instantly
- [ ] Reloading the page keeps the last chosen language
- [ ] First-time visit respects the browser's language if EN/FR
- [ ] No hardcoded strings outside the dictionaries (except the static `<title>` fallback in `index.html`)
- [ ] `document.title` and `<html lang>` follow the selected language
- [ ] `npm run build` passes
